Motir CLI は、Motir エージェントが使うものと同じ MCP サーバーと通信します。ワークスペース単位のトークンを使って、計画から実行までのループを自動化します。実行では、次に着手できる作業項目を取得し、サーバーが生成したプロンプトを受け取り、サンドボックス内のエージェントにその作業項目を実行させます。作業項目が正本であり、CLI はそれを動かす役割です。

## Motir がファイルを置く場所 {#where-motir-keeps-things}

ファイルは 3 つあり、そのうち秘密情報を含むのは 1 つだけです。それはリポジトリの中に置くファイルではありません。以下のパスはすべて移動できます。`motir help files` を実行すると、実際にインストールしたバイナリに基づいて、各ファイルのパスと、それを移動するための環境変数が表示されます。

- `~/.config/motir/config.json` **— 秘密情報を含むため、コミットしないでください**
  認証情報の保管場所です。パーソナルアクセストークンが書き込まれるファイルはこれだけで、`chmod 600` が適用され、`0700` のディレクトリ内に置かれており、サーバー URL をキーにしているため、1 台のマシンで複数の Motir サーバーのトークンを保持できます。設定したエージェントコマンドもここに保存されます。`MOTIR_CONFIG_HOME` または `XDG_CONFIG_HOME` で場所を変更できます。
- `.motir.json` **— 秘密情報なし、コミットして問題ありません**
  ワークスペースのルートに置くプロジェクトのリンクです。このフォルダーが紐付けられているサーバー、ワークスペース、プロジェクトに加えて、任意のリポジトリ上書きマップを持ちます。認証情報は含まないため、バージョン管理に含めるべきファイルです。どのコマンドも現在のディレクトリから上方向にたどってこのファイルを探すので、ルート配下のどのチェックアウトの中からでもコマンドを実行できます。
- `~/.local/state/motir/session-excludes.json` **— 秘密情報なし**
  セッションの除外リストです。ディスパッチに失敗した作業項目を記録し、次の実行が同じ失敗を再び選ばずに先へ進めるようにします。これは認証情報ではなく状態なので、トークンの隣には置きません。サンドボックスは設定ディレクトリを読み取り専用でマウントしており、このファイルに書き込めないことが原因で実行が止まってはならないためです。書き込めない場合、Motir は一度だけ警告して処理を続けます。`MOTIR_STATE_HOME` で場所を変更できます。

## 実行がどこで動くか {#where-a-run-executes}

ディスパッチされたエージェントは、お手元のチェックアウトと、お客様自身のエージェント認証情報を備えたコンテナー内で動作します。コンテナーが何を提供するか、トークンが何を拒否するか、初回の実行でよく起きる失敗については、ここで繰り返さず [{{value:sandboxPage}}](/docs/sandbox) のページにまとめています。CLI を使わずにエージェントを Motir に接続する方法は [{{value:mcpPage}}](/docs/mcp) を、同じ作業ループを HTTP で動かす方法は [{{value:apiPage}}](/docs/api) をご覧ください。3 つの実行形式、セッションブランチ、失敗時のポリシー、トラブルシューティングを含むコマンドの完全なリファレンスは、motir-core の [docs/cli.md]({{value:cliReferenceUrl}}) にあります。

{{part:unreachable}}

コマンドリファレンスに一時的にアクセスできません。このリファレンスは CLI 自身が宣言するカタログから生成されるもので、ここにコピーは置いていないため、今お見せできるものがありません。インストール済みのバイナリで `motir help` を実行すると、同じ表が表示されます。
